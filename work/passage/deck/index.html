Passage

Translate text, documents, photos and speech. It runs on your own hardware when your hardware can handle it, and it names the engine that served every request.

It started as an internal tool for people doing real translation work, and it was paid for. This is the rebuild. The original never answered one question: where did this text actually go?

This is not a feature tour. It is the places where a measurement proved an assumption wrong and the code changed. That includes the ones that went badly: a first number that was wrong, a clever fix that got reverted, and 419 passing tests that were hiding a data leak.

Match the model to the job. Translation is not reasoning, so a thinking model spends its budget deliberating over work that never needed it, and no token limit reliably stops it. Extraction is different. With think:false, the same class of model reads a whole menu photo in 2.6 seconds.

03 / 12

The rule everything else follows

Six of seven models ignored the instruction. So the instruction became code.

6 / 7models mangled protected spans
1line of prompt telling them not to

Every model in the roster was given one sentence containing a URL, an email address and a figure, and an explicit instruction to leave them alone. Six of the seven altered them anyway.

Which one complied is not recorded, because one pass on one sentence is a coin landing the right way, not a compliant model. The six failures are the finding, and they say something about this class of model rather than about six bad ones.

What replaced the instruction

mask   see https://a.co/x for €1,200
       ↓  deterministic, pre-flight
       see ⟦P0⟧ for ⟦P1⟧
       ↓  model never sees the span
unmask see https://a.co/x for €1,200

The model gets text it cannot corrupt, because the fragile parts are not in it. _mask_protected_spans is deterministic, so one test covers it instead of sampling across runs. The test checks the mechanism, not the wording of a prompt that the next model version might quietly stop following.

the standing rule in this codebase Never enforce a model rule by asking for it. Mask it, route it, or validate it, then test that.

It has paid off three times here. URL masking. A speech model with no ability to answer the text instead of reading it. And injection defence that translates embedded instructions literally instead of trusting the model to refuse them.

5x smaller than the 27B, nearly 2x faster, and it scored higher. Before spending VRAM on a bigger model, check whether someone has built a small one for your actual task.

gemma3:1b · source → es → back to English “the board pushed back on the buyback” became “the council regulated the share purchase”

That is the floor, and it is why the 0.8 GB model was cut instead of tuned. It is not rougher than the others. It reports a different event, with the same confidence.

Agreement means average similarity to the other models on the same input. There is no reference translation, so it rewards the mainstream reading and flags outliers. It is triage, not a leaderboard.

Typing retranslates on every 350 ms pause. So the live path drops the hardening preamble, which matters for a file a stranger sent you and does nothing for a box you are typing in yourself. URL masking stays, because that one is correctness.

Cold start, before and after

warming on first request
  [2957, 1875, 1013, …] ms

pre-warming at page load
  [125, 135, 154, …] ms

Warming on first request put the probe, the VRAM load and the user's first keystroke on the same instant. Moving that work to page load made the first interaction about 24x quicker, with no change to the model.

Every background fetch since then copies it, including the Piper voices and the Whisper weights. Threaded, silent on failure, never awaited, never able to block a translation.

One clip, cache cleared, 3 runs each. This is one machine. The ranking should hold elsewhere; the absolute numbers should not be quoted.

Two dependency calls that paid off

CPU over CUDA. ctranslate2 wanted cublas64_12.dll and about 700 MB of wheels for work that already took 0.6 s on CPU. It later turned out to be the only option that works on Apple Silicon, where CUDA does not exist. That was luck, not foresight.

Piper over a general text-to-speech model. It is a VITS model, so it has no capacity to answer the text instead of reading it. A big model would need a prompt asking it to behave. This one cannot do the wrong thing in the first place.

07 / 12

Routing, and the trap inside it

Everything falls back. That's good for users and dangerous for testing.

text
keystroke→probe→translategemma:4b→hosted
document
segment→BYO profile→local/hosted→trace
camera
validate→qwen3-vl:8b→row geometry→composite
voice
whisper→translate→piper·each falls back alone

Voice is three independent decisions, so a missing voice for one language does not push the whole recording off the machine.

That independence hid the subtlest bug here. The engine line was computed from two of the three steps, so it could say “this machine” while the middle step went hosted. The middle step is the one carrying the actual words.

assert meta["stt"] == "local:base"
assert engine == "local:translategemma:4b"
# not: assert response.ok

With no Ollama running, every local path quietly goes hosted and the app looks perfect. So every test here has to answer one question: would this fail if the local engine never ran? If it would not, it proves nothing.

The prove-it pass

419 passing tests, and the app was still lying about where data went.

7adversarial agents
42claims raised
~35reproduced as real

Seven agents that had not written the code drove the real app in a real browser. One per modality, plus degradation, cross-user and mobile. Every claim had to be reproduced before it was accepted.

The tests were not wrong. They were narrow. They covered the one path that happened to be implemented correctly, and a green suite looks the same either way.

Rendered live, clean session, no misconfiguration

A cache hit was booked as “sent out” and metered. The test was engine.startswith("local") and the engine was "cache". Underneath that: the privacy sentence came from a capability probe, not from what actually served the request.

worst finding · two browser sessions, separate cookies User A's private-endpoint output was served verbatim to user B, labelled as B's own engine.

The cache key was (text, target, mode) on one shared backend, with no provider and no session in it. B made zero outbound calls, so nothing looked wrong.

It took two rounds. Round one fixed it and verified against /api/text_translate. The Translate button does not use that route. It ran a bare Thread, ContextVars do not cross into threads, the scope fell back to "shared", and the leak stayed live on the surface people actually click.

09 / 12

Why it took six rounds

All four bugs had the same cause.

Four defects, one shape
Where it showed upThe claimDerived from
cache hit“no model ran, nothing was sent”a process-wide counter every session bumps
response body“runs on this machine”a capability probe taken at page render
voice engine line“this machine”two of the three steps, not the middle one
failed photo“nothing translated yet”a ledger row that was never written at all

All four are the same bug: the app worked out a privacy claim from state it read at render time, instead of recording what happened when it happened.

Six rounds is the cost of fixing that one surface at a time. Each round closed the case in front of it, the reviewer found the next surface, and the tests written each round passed honestly while the bug stayed alive.

The last one, fixed at the shape

with capture_provenance() as prov:
    result = fn(*args)
# ← exception escaped past the record() below
record(engine=…, chars=…)

Photograph a blank wall. The vision model receives the image, answers “no text here”, the backend raises, and the row is never written. /engines then said “Nothing translated yet.” about a photo that had been sent to a hosted model on the app's key.

The fix catches, writes the row, and re-raises, on the path every surface shares. A call that was delivered and then failed is a disclosure. A connection that never opened is not, and saying otherwise would tell an offline user their words had left the machine.

the first cut of that fix — caught by an existing test It named the engine from the label the caller expected to use, and disclosed a send for a file that was rejected before a single byte left.

That is the same bug one level up: an expectation formed before the call, standing in for a record of the call. The only thing that counts as proof now is a row written at the outbound call.

Negative results

What didn't work, and what stays unfixed on purpose.

A number that didn't replicate

Overlay error, single run versus five runs
Reported fromBeforeAfterVerdict
one run17.5 px9.2 pxa halving — and wrong
median of 523.5 px20.5 px~13%, better in 4 of 5

It shipped anyway. It is cheap, it degrades gracefully, and it helps most of the time. But the headline needed a public correction, and it set the rule used everywhere here since: anything model-dependent gets a median across at least 5 runs, reported with how many of them improved.

A fix that got reverted

A per-channel ink map was meant to catch the burgundy headings that the greyscale threshold misses. It found one extra row and one phantom band over blank paper. No better on the numbers, so it was reverted.

Left alone deliberately

The coloured-heading overlay error is real and still open. It needs real OCR line geometry, which is a dependency decision, not a third threshold to tune. Three attempts was enough to learn which kind of problem it is.

Not verified, and not claimed

  • Apple Silicon inference — runners have no Ollama, no GPU
  • Real arm64 speech — the nightly job exists, hasn't run
  • iOS Safari, Android Chrome — emulation isn't a device
  • Real microphones — every speech number came from a synthetic audio fixture, which is the clean input that flatters a small model
  • Latency off this box — one 5090's opinion

The framework trade

NiceGUI made this fast to build and awkward to deploy.

Long sessions drop. Two causes, one already fixed.

Event loop responsiveness during a health check against an unresponsive Ollama socket
Health check vs dead socketWall clock50 ms ticksHeartbeat
four blocking probes on the loop15.31 s0client declares the socket dead
probes moved off the loop2.53 s41connection survives

NiceGUI runs a socket.io heartbeat on the asyncio loop. Block the loop and the heartbeat stops, so the browser reconnects. Median of 5 runs, 5 of 5 improved.

The structural half: three Cloud Run defaults

Cloud Run defaults hostile to a stateful WebSocket app
DefaultEffect on a stateful UI
timeout 300 sthe WebSocket is the request — killed every 5 min
affinity offa reconnect can land where this client never existed
min-instances 0scale-to-zero takes every live session with it

NiceGUI keeps UI state on the server. Elements live in process memory, keyed to a client id. That is why four modalities shipped fast in pure Python with no frontend build, and why scaling out is awkward.

Change the config before rewriting the app, but change it one flag at a time. Two of those three defaults cost nothing and are now set: --timeout=3600 --session-affinity. --min-instances=1 is deliberately not set, because it bills continuously for an app with no users. Listing all three together is what made it tempting to reject the two free ones alongside the one that charges. Affinity is best-effort, so this reduces state loss rather than ending it. unverified: reasoned from the documentation, not observed on the real service.

And the persistence that isn't being built

  • No accounts, no billing, no durable storage. Auth is ported and live-tested, and left unwired on purpose. Abuse prevention sits where the risk is: a signed page token, per-IP rate limits, and size caps
  • No original file is kept, on any surface. The segments and traces carry everything worth reviewing. Keeping the upload adds exposure and a deletion obligation and buys nothing, so policy.py enforces it instead of me remembering it
  • The translation cache stays in-process and ephemeral, on purpose

Portability, and what it takes to ship

The CI matrix caught a real bug the first time it ran.

CI matrix status by runner
RunnerFirst runNowWhat it settled
windows-latestpasspassthe dev box's own assumptions
ubuntu-latestfailpasshost-specific path handling
macos-14failpassarm64, confirmed from runner output
nightly speech · macosnot runnot runreal arm64 speech — still open

A path-redaction helper cut a path down to its filename using the host's separator rules, so a Windows path leaked in full on Linux and macOS. Windows-only testing could never see it. It was caught the first time the code ran anywhere else.

So the code never asks “am I on a Mac?” It asks whether a model is reachable, whether a font resolved, whether the speech stack imported. Checking the platform records a guess. Checking the capability records a fact.

Blocked on a device, not on engineering

  • A real Mac — to settle Apple Silicon inference
  • A phone — to answer for iOS Safari and Android Chrome
  • Ten real voice clips — accents, noise, a phone mic. Half an hour of someone's time settles the base-vs-small question

All of it is minutes of someone's time. Open /diagnostics on the device and paste back what it prints. The page exists so the hardware answers the question instead of an engineer guessing.

What isn't being built, and why

Accounts and billing, because a signup wall in front of a demo mostly measures who bounces off it. A traces dashboard, because there are no real human edits yet, and a chart computed from nothing is worse than no chart. A third overlay heuristic, because three attempts was enough to learn it needs real OCR geometry.
