Codex and Claude Code, on the same work

Same tasks, both agents, both answers published side by side so you can judge for yourself. Five real jobs rather than puzzles, fixed before either one sees them.

David Neish Outline · in progress

Give both agents the same task, publish both results side by side, and let you judge. The outline ships first so you can hold the finished piece to it.

A fixed task set, published up front

The tasks are written and frozen before either agent sees them, and they are listed on this page when the piece lands. Roughly five, each a real job rather than a puzzle: build a small feature from a one-line brief, find a bug from a failing test, refactor across several files, generate a UI for data that already exists, and read an unfamiliar repository and explain what it does.

Both answers, side by side

Every task shows what each agent produced, not a score. The interesting part of this comparison is the difference in approach, and you cannot see that in a number. Where one of them did something I would not have thought of, that gets called out.

What the rest of the field is doing

Before running anything I want to know how these are already being evaluated, what those benchmarks actually measure, and where they stop being useful. Reverse-engineering the existing evaluations is half the work, and it is the half that stops this from being one more anecdote.

Where each one earns its keep

The likely answer is not that one wins. It is that they are suited to different shapes of task, and knowing which is which is worth more than a leaderboard position.

How I will avoid fooling myself

One run is not a result. Anything model-dependent gets repeated, and where a finding does not hold up on a second pass, the piece says so.
