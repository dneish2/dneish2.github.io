Engineering notes · Passage

A prompt is not a mechanism

Four measurements from building a translation workspace, each of which changed the code: where models ignored an explicit instruction, where a purpose-built small model beat a big one, where my own headline number failed to replicate, and why one defect took six review rounds to kill.

David Neish

Passage translates text, documents, photographs and speech. It runs on a local model when one is reachable, on your own endpoint if you bring one, and on a hosted model otherwise — and it names, per request, which of those actually answered. It began as an internal tool for people doing real translation work, and it was paid for.

None of that is what makes it worth writing about. What follows is the handful of times a measurement contradicted something I believed, including the times the thing I believed was my own previously published number.

1. Six of seven models ignored the instruction

Translation has a class of spans that must survive untouched: URLs, email addresses, figures, currency. The obvious approach is to say so in the prompt. I did, explicitly, and then measured whether it held.

6 / 7models altered protected spans
1line of prompt saying not to

Every model in the roster got one sentence containing a URL, an email address and a figure, plus an instruction to leave them alone. Six of the seven mangled them anyway. Which one complied isn’t interesting and I didn’t record it: one pass on one sentence is a coin that landed the right way, not a compliant model. The six failures are the finding, and they are a property of the model class rather than of six bad models.

So the instruction stopped being an instruction. Fragile spans are extracted before the call, replaced with opaque placeholders, and restored after:

mask    see https://a.co/x for €1,200
        ↓   deterministic, pre-flight
        see ⟦P0⟧ for ⟦P1⟧
        ↓   the model never sees the span
unmask  see https://a.co/x for €1,200

The model is now handed text it cannot corrupt, because the corruptible parts aren’t in it. And because masking is deterministic, it is testable once rather than sampled across runs — the test asserts the mechanism, not the wording of a prompt that the next model upgrade could quietly stop honouring.

the rule this produced

Never enforce a model invariant by asking for it. Mask it, route it, or validate it — then test the mechanism.

It has since paid off twice more in the same codebase. Local speech synthesis uses Piper, a VITS model rather than a language model, so it is structurally incapable of answering the text instead of reading it aloud — where a general TTS model needs a prompt asking it to behave, a small specialised one makes the failure unreachable. And prompt-injection defence translates embedded instructions literally rather than trusting a model to decline them.

2. Thinking models are the wrong tool — for this task

The qwen3 family looked like a silent failure through Ollama’s OpenAI-compatible endpoint: content came back empty every time. The answer was going to a reasoning channel that endpoint doesn’t expose. Through the native API the channels stay separate and the answer arrives — which is how I found the actual problem.

qwen3:30b spent 8,786 characters deliberating a one-line translation and still produced no answer, on top of a 2,048-token reserve. That isn’t a budget you tune. Translation is transduction, not reasoning; there is no reserve that reliably bounds deliberation a task never needed.

The tempting fix is think: false. On a translation prompt it makes things worse — the model writes its reasoning into the answer. But the same flag on the same model class is exactly right for extraction, where deliberation is pure cost: with it, qwen3-vl:8b reads a full menu photograph, accents and currency intact, in 2.6 seconds, entirely offline.

Same model, same flag, opposite verdicts, decided by the shape of the job. Thinking models are kept out of the default translation roster and left selectable.

The 4B outscores the 27B from its own family at a fifth of the size and nearly twice the speed. Before spending VRAM on a bigger model, check whether someone has built a small one for your actual task.

The floor is more interesting than the ceiling. gemma3:1b rendered “the board pushed back on the buyback” as “el consejo reguló la compra de acciones” — “the council regulated the share purchase.” That is not a rougher translation. It is a different claim, stated with identical confidence. Reaching for the tiniest model to save memory buys a confidently wrong answer, which is worse than a slow one.

One caveat I’d want applied to my own table: agreement means mean similarity to the other models on the same input. There is no reference translation to score against, so it rewards the mainstream reading and flags the outlier. It is triage, not a leaderboard — a model can be right and alone.

4. One run is not a result

An overlay-alignment fix — painting translated text back onto a photograph in the right place — measured 17.5 px error before and 9.2 px after. A halving. I nearly shipped that number.

Overlay error: one run versus the median of five
Reported fromBeforeAfterWhat it actually says
a single run17.5 px9.2 pxa halving — and not reproducible
median of five23.5 px20.5 px~13%, better in 4 of 5 runs

The vision model’s box predictions vary noticeably run to run, so a single before/after pair mostly measures which run you got. The fix shipped anyway — it is cheap, it degrades gracefully, it helps most of the time — but the honest headline is “somewhat better on average,” and one of the five runs got worse.

the rule this produced

Anything whose result depends on a model’s output gets reported as the median across at least five runs, together with how many runs improved. Deterministic changes — masking, routing, parsing — can be measured once. The distinction is whether sampling is in the loop.

The same discipline is why a shipped default in that repo carries a written note that the evidence under it doesn’t count. Every speech measurement so far used a fixture generated by a text-to-speech model: no accent, no background noise, no clipping, no phone-mic band limiting. That is structurally the easiest possible input for a recogniser, and the gap between Whisper sizes is precisely the gap that only opens on hard audio. So the small model stays, the protocol that would settle it is written down, and the claim above it is marked unproven rather than quietly inherited.

A related habit, from the same instinct: a screenshot difference is not a bug report until the computed style is checked. Two “bugs” found during a UI pass turned out to be hover artifacts from the automation driving the browser.

5. 419 passing tests, and one defect wearing four costumes

An adversarial review — agents that hadn’t written the code, driving the real app in a real browser, one per modality plus degradation and cross-user — found a cross-user data leak and three privacy overclaims. The suite was green throughout. The tests weren’t wrong; they were narrow, and narrowness looks exactly like correctness until someone opens a browser.

The worst finding: user A’s translation, produced on A’s own private endpoint, served verbatim to user B and labelled as B’s engine. The cache key was (text, target, mode) on one shared backend — no provider, no session. Zero outbound calls for B, so nothing looked wrong from any angle a single-session test can see.

It took six rounds to converge, and that is the part worth writing down. Not because the defects were hard, but because they were all the same defect:

Four defects and the single shape they share
Where it surfacedThe claim it madeDerived from
cache hit“no model ran, nothing was sent”a process-wide counter every session bumps
response body“runs on this machine”a capability probe taken at page render
voice engine line“this machine”two of three steps, not the middle one
a failed photo“nothing translated yet”a row that was never written at all
the shape

The app deriving a privacy claim from state read at render time, instead of recording what happened when it happened.

Six rounds is what fixing a shape one surface at a time costs. Each round closed the instance in front of it and wrote a test that passed honestly; the reviewer then found the next surface. The lesson isn’t “review more” — it’s that when the third instance of a defect arrives, the defect you are looking at is not the one to fix.

The last instance is my favourite, because it is the same mistake twice. Photograph a blank wall: the vision model receives the image, answers “no text here,” the backend raises, and the exception escapes past the bookkeeping at the end of the function. The page then reported “Nothing translated yet” about a photograph that had demonstrably been sent to a hosted model on the app’s key.

with capture_provenance() as prov:
    result = fn(*args)
# ← the exception escaped past everything below
record(engine=…, chars=…)

A call that was delivered and then failed is still a disclosure — a 429, a timeout, an empty reply all happen after your text is on someone else’s computer. A connection that never opened is not, and saying otherwise would tell an offline user their words had left, which is a lie told to precisely the person who chose the app for that reason. So the fix catches, books and re-raises, on the path every surface shares.

And then the first version of that fix reproduced the original defect one level up. It named the engine from the label the caller expected to use — an expectation formed before the call — and so disclosed a send for a file that validation had rejected before a single byte left. An existing test caught it, one whose docstring had already stated the rule: rejected before anything leaves, and nothing is booked. Provenance written at the moment of the outbound call is now the only accepted proof of departure.

6. What I didn’t build

Named because they were tempting, not because they were forgotten.

  • Accounts, billing, durable storage. The auth verification is ported and tested, and deliberately unwired. A signup wall in front of a demo mostly measures who bounces at it. Abuse prevention lives where the actual risk is: a signed page token, per-IP rate limits, size caps.
  • A traces dashboard. The plumbing records machine output, human edits and edit rate per engine. There are no real human edits yet, so a chart over that data would be a chart computed from nothing.
  • A third overlay heuristic. Two were tried, one made it worse, a third measured no better and was reverted rather than kept for the idea’s sake. The residual error needs real OCR line geometry, which is a dependency decision and not a tuning one. Three attempts was enough to learn what kind of problem it is.
  • A minimum instance on Cloud Run. Two of the three config defaults that hurt a stateful WebSocket app cost nothing to change and are set. The third bills continuously, and this app has no users yet.

The thread through all of it: the useful output of a project like this isn’t the feature list, it’s the set of beliefs it forced me to drop. Four of them are above, along with the evidence that killed each one.
